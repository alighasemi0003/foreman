# Encryption key provisioning (F-004 / F-005)

Foreman encrypts selected database fields via `EncryptValue` / `Encryptable`
(`encrypted-` prefix + `ActiveSupport::MessageEncryptor`).

## Key load order (native)

1. `ENV['ENCRYPTION_KEY']` (stripped; blank/whitespace ignored)
2. `ENV['ENCRYPTION_KEY_FILE']` (file contents, stripped)
3. `EncryptionKey::ENCRYPTION_KEY` from `config/initializers/encryption_key.rb`
   (generated by `rake security:generate_encryption_key`; **gitignored**)

If no key is configured, or encryption raises an error, **new secret writes
refuse to store plaintext** (fail closed) and the ActiveRecord save aborts.
Reads of existing plaintext remain possible until migrated. Decryption
failures leave the ciphertext unread (legacy read behavior).

Empty `ENCRYPTION_KEY=` (common with Compose `${ENCRYPTION_KEY:-}`) does **not**
count as a configured key. Production boot logs an error when no key is found;
secret writes still fail closed. Use `rake security:check_encryption_key` as a
preflight.

## Models that encrypt fields

| Model | Attribute |
| --- | --- |
| `AuthSourceLdap` | `account_password` |
| `ComputeResource` | `password` |
| `HttpProxy` | `password` |
| `Nic::Base` (BMC) | `password` |
| `JwtSecret` | `token` |
| `KeyPair` | `secret` (compute SSH private key) |
| `ForemanRegister::RegistrationFacet` | `jwt_secret` |
| Encrypted `Setting` values | `value` |

Compute resource private keys can also be downloaded as passphrase-protected
PEM via `POST .../key_pairs/:id/export` (passphrase in the POST body only).
Plain `GET .../key_pairs/:id` remains for SSH/automation compatibility after
reauthentication.

Built-in rake encrypt helpers cover LDAP + compute resources
(`rake db:encrypt_all`). Prefer `security:encrypt_legacy_secrets` for a full
Encryptable inventory including `JwtSecret`.

## Local Docker (lab)

Never commit real key material.

```bash
cp .env.example .env
# Generate once (example — do not share this value):
#   python3 -c 'import secrets; print(secrets.token_hex(32))'
# Put the result in .env as:
#   ENCRYPTION_KEY=<64-hex-chars>
```

Compose passes `ENCRYPTION_KEY` / `ENCRYPTION_KEY_FILE` into `app`, `worker`,
and `orchestrator` (same env via YAML anchor).

Optional file mount (create the host file first so Docker does not create a directory):

```bash
mkdir -p secrets
umask 077
# write 64 hex chars into secrets/encryption_key (never commit)
chmod 600 secrets/encryption_key
```

```yaml
# add under app volumes when using a file instead of ENCRYPTION_KEY:
#   - ./secrets/encryption_key:/run/secrets/foreman_encryption_key:ro
# and in .env:
#   ENCRYPTION_KEY_FILE=/run/secrets/foreman_encryption_key
```

Restart/recreation must reuse the **same** key. Changing the key without a
decrypt→re-encrypt plan permanently loses access to ciphertext.

## Non-Docker

```bash
bundle exec rake security:generate_encryption_key
# writes config/initializers/encryption_key.rb (gitignored)
# restart all app processes, then optionally:
bundle exec rake security:check_encryption_key
bundle exec rake security:encrypt_legacy_secrets   # dry-run by default
```

## Legacy plaintext remediation

If secrets were saved while the key was missing, they may lack the `encrypted-`
prefix.

### Procedure

1. Confirm a usable key: `rake security:check_encryption_key`
2. Inventory (ids/counts only): `rake security:encryption_inventory`
3. Take a fresh database backup (`pg_dump` / snapshot). Keep the file path.
4. Dry-run: `rake security:encrypt_legacy_secrets` (default; no writes)
5. Apply: `CONFIRM=YES DRY_RUN=0 BACKUP_PATH=/path/to/backup.sql.gz rake security:encrypt_legacy_secrets`
6. Re-run inventory; plaintext candidate count should be zero for remediated models
7. Verify JWT / compute / LDAP still work with the **same** logical secrets

### Guarantees

- Uses model encryption (`Encryptable` before_save / `encrypt_field`)
- Skips values that already have the `encrypted-` prefix (no double encryption)
- Skips values that look like MessageEncryptor ciphertext missing a prefix
- Preserves JwtSecret HMAC material (does **not** rotate tokens; existing JWTs remain valid)
- Logs model, id, field, outcome — never secret values
- Safe to re-run after interruption

### Do not

- Rotate `ENCRYPTION_KEY` merely to encrypt existing rows
- Use broad `update_all` / raw SQL that bypasses `encrypt_field`
- Print or export secret column contents in tickets or CI logs

## Placeholders only

Examples in docs use `<ENCRYPTION_KEY>` / empty `.env.example` entries — never
real keys.
